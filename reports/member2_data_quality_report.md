## 2. 重复行为与异常高频规则

当前输入字段 `time` 只精确到小时。因此，同一用户在同一小时内可能真实发生多次浏览、收藏、加购或购买，不能把所有相同四元组直接判定为脏数据。

当前规则：

- 相同四元组出现 **2～59 次**：全部保留；
- 相同四元组出现 **60 次及以上**：标记为异常高频/疑似恶意重复组，仅保留首次记录，其余删除；
- 阈值 60 为包含边界；
- 由于缺少分钟/秒级时间戳，本规则属于**同小时代理规则**，不能声称识别了“一分钟内重复 60 次”。

## 4. 清洗规则

1. 关键字段缺失记录剔除。
2. `behavior_type` 仅允许 1/2/3/4，并映射为 pv/fav/cart/buy。
3. ID 要求为非空正整数且可安全表示为 Int64/SQLite INTEGER；不对 ID 使用 IQR/3σ。
4. `time` 按 `%Y-%m-%d %H` 严格解析；只有明确配置业务合法时间范围时才执行越界过滤。
5. `item_category` 标准化为 `category_id`。
6. 生成 `behavior_name`、`behavior_date`、`behavior_hour`、`weekday`。
7. 普通四元组重复不删除；只有同一小时内相同四元组达到 60 次及以上时才视为异常高频并折叠为一条。
8. 使用分块读取和磁盘 SQLite 统计，保证跨 chunk 的全局规则一致。

## 7. 结论与后续使用

本次全量数据中存在大量相同四元组的重复行为，但最大单组出现次数为 22，低于异常高频阈值 60，因此没有记录被按异常高频规则删除。当前最终 clean 数据保留全部 12,256,906 条记录。

Member 3 与后续 EDA 应基于 `data/processed/user_behavior_clean.parquet`（或 clean CSV）重新计算正式统计指标。旧版“所有四元组重复均删除”的口径已废弃，旧版 clean 行数、删除比例及相关结论不得继续作为最终口径。
